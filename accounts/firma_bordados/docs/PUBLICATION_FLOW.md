# Punto 3 – Flujo de publicación, hipótesis y métricas (Facebook/Instagram)

## Objetivo
Definir el proceso completo desde la generación de una idea de contenido hasta la captura y análisis de métricas, todo dentro del ecosistema GrowthOS y enfocado exclusivamente en Facebook e Instagram.

## Flujo paso a paso

| Paso | Acción | Detalles | Responsable / Herramienta |
|------|--------|----------|---------------------------|
| **1. Ideación** | Crear una nueva pieza en el CSV `pieces_firmabordados.csv` | - `Estado = Idea`<br>- Asignar un `ID_Pieza` (siguiendo patrón `CNT-####` o manteniendo legado `FB-####` si se decide no cambiar validador).<br>- Completar campos básicos: `Titulo`, `Tipo_Contenido`, `Plataforma`, `Objetivo`, `Categoria`, `Formato`, `Asset_Ref_Confirmado` (nombre de archivo en Drive), `Drive_ID`, `Fuente`, `Prioridad`, `Dificultad_Produccion`, `Es_Reutilizable`.<br>- Opcional: asignar `Hipotesis_ID` (HB‑xxx) si la pieza se crea para validar una hipótesis de marketing. | Equipo de contenido / Script de ingreso manual o interfaz sencilla. |
| **2. Revisión de Gate 3 (Copy y Assets)** | Validar que el copy cumple con la plantilla correspondiente y que el asset está listo. | - Usar **Plantillas de Copy V2** según objetivo (venta, información, confianza, educación) y CTA (WhatsApp, llamada, visita, descargar).<br>- Verificar que el asset (foto/video/PDF) exista en Google Drive con el `Drive_ID` correcto y que esté en la carpeta adecuada (ej. `/Firma Bordados/` o `/Catalogos/`).<br>- Si todo es correcto, cambiar `Estado` a `Pendiente de Producción`. | Líder de contenido o diseñador. |
| **3. Preparación de programación** | Preparar los parámetros para publicar vía Meta Graph API. | - Construir el mensaje de copy (texto completo).<br>- Preparar el medio: subir el asset a una carpeta accesible por la API (si no está ya) o asegurar que el `Drive_ID` corresponde a un archivo compartido públicamente o con token de acceso.<br>- Definir la hora de publicación basada en los horarios de impacto:<br>  • Mañana: 08:30‑09:30<br>  • Tarde: 14:00‑15:30<br>  • Noche: 19:30‑21:00<br>  • Domingo (reel resumen): 20:00‑21:00. | Community Manager / Soporte técnico. |
| **4. Publicación (Gate 4)** | Ejecutar la publicación en Facebook e Instagram usando Meta Graph API v26. | - Llamada a `/me/feed` (FB) o `/me/media` (IG) con parámetros: `message`, `published=false` (para programar), `scheduled_publish_time` (timestamp UNIX), `url` o `attached_media` según tipo.<br>- La API devuelve un `creation_id` y luego un `post_id` cuando se publica. <br>- Al recibir la respuesta con `is_published = true`, actualizar el CSV:<br>    - `Estado = Publicado`<br>    - `Fecha_Ultima_Publicacion` = fecha y hora de publicación.<br>    - `Meta_Publication_ID` = ID devuelto por la API.<br>    - `Asset_Ref_Candidato` (opcional) si se usó una variante. | Script de automatización (ej. `record_facebook_publication_after_approved_publication_review.py` adaptado) o herramienta de Business Suite. |
| **5. Difusión táctica** | Aplicar acciones de alcance específicas por plataforma. | **Facebook**: Compartir la publicación de la tarde en al menos 3 grupos locales de Piedras Negras/Eagle Pass; incluir número de WhatsApp al inicio del copy.<br>**Instagram**: Agregar stickers de ubicación y enlace a WhatsApp en Historias; usar hashtags predefinidos (#FirmaBordados, #BordadoPN, #UniformesPersonalizados, etc.); convertir al menos 2 de las 3 publicaciones diarias en Reels (7‑10 s) con música en tendencia. | Community Manager (manual) o script de repost. |
| **6. Métricas 24 h y 72 h (Gate 6)** | Extraer y almacenar métricas de desempeño. | - Ejecutar scripts existentes:<br>  • `extract_metrics_24_72.py` (o variantes específicas para video/Reel).<br>  • `test_instagram_insight_metrics.py` para validar extracción de IG.<br>  • `analyze_facebook_windows_and_video_insights.py` para métricas de ventanas de tiempo.<br>- Los scripts deben leer el `Meta_Publication_ID` (o `Asset_Ref_Confirmado` si se usa) y guardar resultados en el CSV de métricas diarias (`*_Corte_Diario_Metricas_*.csv`) o en una tabla de métricas dedicada.<br>- Campos a actualizar en el CSV de piezas (opcional, para trazabilidad):<br>    - `Reacciones_24h`, `Comentarios_24h`, `Compartidos_24h`<br>    - `Reacciones_72h`, `Comentarios_72h`, `Compartidos_72h`<br>    - `Alcance_24h`, `Alcance_72h` (si está disponible).<br>    - `Ultima_Sincronizacion` = timestamp de extracción. | Equipo de analítica / Scripts automáticos (cron cada día a las 22:00). |
| **7. Validación de hipótesis** | Comparar resultados contra la hipótesis asociada (HB‑xxx). | - Definir umbrales de éxito previamente acordados (ej. ≥ 30 interacciones totales a 24 h, CTR a WhatsApp ≥ 2 %, crecimiento de seguidores ≥ X%).<br>- Si la pieza cumple, marcar `Reconciliacion_Estado = Validado` y `Reconciliacion_Confianza = High`; en caso contrario, `No Validado` / `Low` y guardar lección en `Nota_Taxonomia`.<br>- Registrar el resultado en el CSV de métricas o en un archivo de hipótesis (`hypothesis_log.csv`). | Analista de crecimiento. |
| **8. Retroalimentación y ajuste** | Usar aprendizajes para mejorar futuras piezas. | - En reuniones semanales de revisión de gates, revisar el porcentaje de hipótesis validadas.<br>- Ajustar plantillas de copy, horarios o tipos de contenido según patrones emergentes (ej. los Reels con música X generan +40 % interacciones).<br>- Actualizar el calendario de contenidos y las guías de copy según lo aprendido. | Líder de growth + equipo de contenido. |
| **9. Archivo y reporte** | Mantener historial y generar reportes. | - Cada mes generar un reporte Markdown (similar a `export_facebook_publication_batch_*_md`) que incluya: total de publicaciones, interacciones medias, mejores y peores performing, hipótesis validadas vs. no validadas, recomendaciones de copy/format.<br>- Guardar el reporte en `auditoria_firma_bordados/reportes/` o en el repositorio GrowthOS para referencia histórica. | Equipo de growth. |

## Consideraciones técnicas

- **Identificador de pieza**: Si se mantiene el legado `FB-####`, ajustar el validador en `growthos/core/models.py` para aceptar ambos patrones o crear un campo separado `Legacy_ID`. Por simplicidad en esta fase, se sugiere usar el patrón `CNT-####` para nuevos registros y mantener los existentes como están.
- **Drive_ID**: Obtenerlo desde la URL de compartir de Google Drive (`https://drive.google.com/file/d/{{Drive_ID}}/view`). Asegurarse que el archivo esté compartido con “Cualquiera con el enlace puede ver” o usar un token de servicio si se prefiere acceso privado.
- **Meta Graph API**: Requiere token de acceso de largo plazo o sistema de renovación vía OAuth. Los scripts existentes (`record_facebook_publication_after_approved_publication_review.py`) ya manejan este flujo; adaptarlos para leer los campos del CSV y programar la publicación.
- **Métricas**: Los scripts de extracción ya esperan ciertos campos (`Meta_Publication_ID`, `Asset_Ref_Confirmado`, `Fecha_Ultima_Publicacion`, etc.). Asegurarse de que esos campos estén poblados antes de ejecutar la extracción.
- **Manejo de errores**: En caso de fallo en la publicación (API error, token expirado, asset no disponible), dejar la pieza en `Estado = Idea` o `Pendiente de Producción` con una nota en `Nota_Taxonomia` y notificar al responsable vía Slack/email.

## Próximos pasos (sin hacer cambios todavía)

1. **Validar el flujo con una pieza piloto**: elegir una pieza simple (ej. una imagen de trabajo del día) y seguir manualmente los pasos 1‑8 usando las herramientas existentes (copiar y pegar copy, programar vía Business Suite, extraer métricas con los scripts).  
2. **Documentar los umbrales de éxito** para cada tipo de hipótesis (venta, interacción, educación) basado en los datos históricos disponibles en los cortes diarios de métricas.  
3. **Crear o actualizar un script de orquestación** (por ejemplo, `run_publication_cycle.py`) que lea el CSV, identifique piezas en `Estado = Pendiente de Producción` con hora de publicación cercana, ejecute la publicación, y luego, a las 22:00, ejecute la extracción de métricas.  
4. **Programar una reunión semanal de revisión de gates** para analizar el porcentaje de hipótesis validadas y ajustar tácticas.  
5. **Una vez validado el flujo piloto**, considerar automatizar la generación de IDs y el movimiento de estados mediante el mismo script, reduciendo la intervención manual.

Con este punto 3 se completa el ciclo de creación, publicación y análisis de contenido para Facebook e Instagram dentro de GrowthOS, listo para ser implementado y monitorizado.
